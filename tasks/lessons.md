# Lessons

Rules distilled from corrections. Review at session start.

- (none yet)
- Workflow scripts are JS template literals: never put inline backticks (`code`) inside an agent prompt; use single quotes. Validate with `node --check` (only the top-level `return` may be reported) before launching.
- The harness's template/scratch database names must carry a run id; anything shared by concurrent test runs (fixed DB names, "drop leftovers" at setup) will destroy a sibling run's state.
- Adversarial review pays for itself: three private-group-name leaks, a missing signed-media route and three Supabase deploy blockers survived every "green" build and were only found by agents told to construct a bypass, not to confirm the code.
- `renderToStaticMarkup` escapes text; assert against escaped copy (`Couldn&#x27;t`) or the test fails on correct code.
- A file in Next's `public/` shadows a same-path route handler — committed placeholder `.well-known` files silently beat env-driven routes.
- Concurrent test runs sharing one Postgres need a run id in every database name; a fixed template plus "drop leftovers at setup" destroys a sibling run.
- Cross-journey isolation needs random name tails, not sequential ones: trigram search matched two journeys' fixtures that differed by one character.
- A test must never hardcode a fact about the machine it happens to run on. `helpers.test.ts` asserted the Postgres socket peer was `127.0.0.1`, which is true locally and false in CI (the client crosses a Docker bridge, so the peer is the gateway, `172.18.0.1`). Read the environment fact from the environment (`host(inet_client_addr())`) and assert against that — the assertion gets stronger, not weaker.
- When a CI job is red and its log is unreadable, fixing the readability is a real step, but say plainly that the failure itself is still unfixed rather than reporting the log fix as progress on the failure.
- A workflow-level `env:` block reaches every job. CI's placeholder Supabase keys (there so the build jobs have a well-shaped environment) silently overrode the real local-stack keys in the e2e job, because the stack suite resolves configuration from `process.env` first. When two steps in a job need different environments, the one that needs the real values must load them explicitly — and assert early that they agree, so the mismatch is named rather than surfacing as a signature error three tests later.
- "Do not hang on it" in a comment is not a guard in the code. `maplibre.ts` resolved on `load` or `error` but had no deadline, so a style host that accepts the request and never replies left the map unbuilt forever — no camera, no `map_objects`, an Earth screen showing no one. Any wait on external events needs a deadline as well as the events.
- A test suite that reaches the public internet is not hermetic, and the failure shows up as a product bug on someone else's network. E2E 10 was the only journey touching the map, so a third-party tile CDN stalling from GitHub's network failed exactly one journey and looked like a product defect.
- Only a journey that moves real bytes proves a media path. Component tests, the storage tests and the whole database suite were green while every photo and voice message was unviewable by its recipient: the client signed Storage URLs as the viewer, which the bucket policy allows for the owner alone, and the server route built for exactly this (`GET /api/media/:bucket/:key*`) had no caller. DOD-02's "no journey sends a photo" was the whole gap.
- A browser-native fetch (`<img>`, `<audio>`, `<video>`) cannot send a bearer. When a route exists for those elements, the mount must accept the session cookie for that route — and only that route, only on GET — or the route is unreachable from the one place it is meant to serve.
- `page.waitForResponse` predicates take the RPC name from `@earth/api`'s manifest (`RPC.contextResolveAndSet` → `/rpc/context_resolve_and_set`), never a guess from the client method's name; the gateway log shows which calls actually happened when one times out.
- An optional dependency is a silent hole. `ServerDeps.storage` was optional "so the rest of the tier runs without it", the web mount's client adapter never forwarded `storage`, and `GET /api/media/*` answered `internal` in every environment while every layer's tests stayed green. When a route needs a dependency, the mount that serves that route must fail loudly without it — and one journey that fetches real bytes catches all three links (no caller, no credential, no dependency) at once.
- Journeys that create a Live must end it: a room left on camera by a failed run sat on the map at the same centroid as the next run's, and two co-located Lives are one cluster, not two pins. Leave the room at the end, and assert the pin *or* the cluster that opens to it.
- `curl` and the browser do not share a network. In this container `curl` reaches the third-party style host through the proxy while Chromium fails it at once (`ERR_CERT_AUTHORITY_INVALID`: the browser does not trust the proxy's CA), so every local map journey ran against a failed style and its markers sat under the header, while CI's browser reached the host and stalled instead. Two environments, two failure modes, one third-party dependency — serving the style from the app itself is what makes local and CI the same run.
